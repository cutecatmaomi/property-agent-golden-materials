# Enact 确定性前置守卫

将本段作为现有技能的接入约定。守卫的实际执行点在 Enact 的请求入口或编排器中，位于登录与输入检查之后、任何 LLM 调用之前。入口调用本包原版 `response_policy.py` 中的 `classify_message`，再根据返回码分流。已验证的楼盘 ID 由服务端传入。

1. 用 NFKC 归一化，再调用 Unicode `casefold()`，只保留类别以 `L` 或 `N` 开头的字符。
2. 用规范化文本建立风险副本。在风险副本中删去所有“跳楼机”“跳樓機”。风险副本命中任一红线词或下面的正则时，返回 `RED_LINE`。
3. 用完整规范化文本匹配人工服务词表。命中任一词时，返回 `USER_REQUEST`。同时命中时先走 `RED_LINE`。
4. 两组均未命中时，继续 Golden Questions 规划、检索和业务流程。
5. 两类命中都由 `fixed_reply` 返回下方原文。界面直接展示 `reply.text`，短路规划、检索、回复生成和业务写入。`reason_code` 保留对应值，`red_line` 仅在红线时为真。`contact_channel=PHONE`、`created=false` 表示仅提供电话号码。
